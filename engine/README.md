# Движок: этапы 1–3

Ядро графического движка Vishar Color Study: загрузка фото, рабочая копия, Worker + WebGL2, Lab, Values, Notan, Temperature (этап 1); пипетка, палитра, карточка цвета, сравнение и Highlight (этап 2); Simplify и Drawing с экспортом SVG (этап 3). Интерфейса приложения здесь нет. `index.html` открывает отладочную страницу: она гоняет движок и показывает цифры по целям этапа.

Тестовый адрес: https://engine.vishar-color-study-bench.pages.dev (preview-ветка `engine` проекта Pages `vishar-color-study-bench`, стенд Stage 0 на основном адресе не тронут).

## Как устроено

| Слой | Где | Что делает |
|---|---|---|
| `src/core/` | чистый TS, работает в Node и в Worker | цвет (sRGB, Lab, luma), разбор заголовков JPEG/PNG/WebP/HEIC, гистограммы, пороги Values/Notan, нейтраль Temperature, CPU-эталон рендера |
| `src/gpu/` | Worker, WebGL2 | рабочая копия в текстуре с mip-уровнями, гауссово сглаживание, буфер анализа `(L*·2.55, a*+128, b*+128, luma)`, шейдер видов |
| `src/worker/engine.worker.ts` | Worker (Comlink) | открытие фото, кэш анализа по уровню сглаживания, рендер, выбор уровня по тапу, сверка GPU и CPU |
| `src/client.ts` | главный поток | передаёт `<canvas>` в Worker (`transferControlToOffscreen`, запасной путь через ImageBitmap), склеивает частые события слайдера |

Открытие фото:
1. Размер и EXIF-поворот читаются из заголовка, для HEIC берётся самый большой `ispe`. Если размер не найден, делается декодирование в 64 px ради пропорции.
2. `createImageBitmap(blob, { resizeWidth, resizeHeight, resizeQuality: 'high' })` сразу отдаёт рабочую копию (длинная сторона 1600). Полный кадр в память не попадает.
3. Если декодер не умеет уменьшать, работает запасной путь: одно полное декодирование (только когда `w×h×4` меньше бюджета, по умолчанию 512 МБ), уменьшение на canvas и сразу `close()`.
4. Если и это не вышло, длинная сторона уменьшается: 1600 → 1200 → 800. Ступень попадает в отчёт.

Слайдер меняет только uniform-ы шейдера, пороги пересчитываются на CPU по готовой гистограмме (256 корзин), поэтому кадр не зависит от размера фото. Новое сглаживание считается один раз и кэшируется.

## Решения по умолчанию

- Values: шкала L*, 9 уровней, k-means по числу пикселей. Запускаются два старта (линейный и по квантилям), побеждает лучшая подгонка.
- «Как в оригинале»: шкала luma Rec.601, k-means только с линейным стартом, как в `experiments/original_web/src/a2.py`. На четырёх эталонных фото совпадение с порогами Color Study 99,6 / 90,9 / 99,8 / 97,2 %. Пейзаж ниже 95 %, поэтому алгоритм оригинала не считается полностью восстановленным.
- Вес √count и равные интервалы доступны как опции.
- Notan: порог Otsu по L*. Есть режим медианы (правило оригинала) и «авто»: медиана, пока она не попадает в доминирующий ровный тон.
- Temperature: тепло считается как проекция (a*, b*) на оттенок 60°, нейтраль равна медиане фото. Есть абсолютная нейтраль и три вида: карта, карта со светлотой исходника, 2 цвета. Формула оригинала не восстановлена (TECHNICAL_RESEARCH F21), это наше определение.

## Этап 2: цвет

| Что | Где | Как работает |
|---|---|---|
| Пипетка | `Engine.pickColor(u, v, size)` | среднее квадрата 1/3/5/11 px в линейном RGB по несглаженной рабочей копии, плюс патч 21×21 для лупы |
| Карточка цвета | `core/colorinfo.ts` | HEX, RGB, CMYK, HSL, HSV, LAB, LCH, XYZ, xyY; Value (L*), тон и хрома LCh, имя по-русски, тёплый/холодный по той же оси, что Temperature, дополнительный цвет (тон LCh + 180°, хрома ужимается до охвата sRGB) |
| Сравнение | `compareColors(a, b)` | ΔE2000 и разницы B − A по Value, теплу, тону и хроме |
| Палитра | `core/palette.ts` | сетка ~200 тыс. точек, k-means++ (k = 24) в Lab; Dominant по площади со слиянием близких (ΔE2000 < 6, 0 = без слияния); Range на равных шагах L* между 1 и 99 перцентилем, в каждой полосе берётся самый частый кластер; Accents: насыщенные точки вдали от Dominant, свой k-means, оценка хрома × удалённость × √доля |
| Маркеры | там же | у каждого образца точка на фото: из ближайших по цвету мест выбирается ровное (проба 5×5, для тонких линий 3×3 или 1 px). Цвет образца берётся в этой точке, поэтому тап пипеткой по маркеру возвращает именно его. `markerDE` показывает отличие от среднего цвета группы |
| Highlight | шейдер, вид 4 | ΔE2000 до выбранного цвета на GPU, допуск 0…50; «подсветка» гасит остальное в серый, «контур» рисует пунктир по краю совпадений. Слайдер меняет только uniform, гистограмма ΔE и доля фото в допуске считаются по сетке один раз на цвет |

Решения по умолчанию: Dominant 6, Range 12, Accents 6, слияние ΔE 6, проба пипетки 5×5, допуск Highlight 10. Цвета палитры реально есть на фото (а не средние кластера).

## Этап 3: Simplify и Drawing

Оба считаются на CPU в Worker по рабочей копии; GPU только показывает готовый результат (вид 5, текстура с мипмапами). Главный поток не ждёт.

| Что | Где | Как работает |
|---|---|---|
| Clustering | `core/simplify.ts` | суперпиксели SLIC (24…1700 сегментов по 9 шагам Details) на копии ≤ 0,5 МП, соседи ближе порога ΔE76 сливаются (порог падает с ростом Details, площадь слитой области ограничена, чтобы градиент не стекал в одно пятно), мелкие области поглощаются соседом с самой длинной границей, метки уточняются на полной копии по цвету. Каждое пятно красится своим средним цветом (линейный RGB) |
| Graph | там же | Felzenszwalb–Huttenlocher на копии ≤ 0,5 МП, рёбра сортируются корзинами по 0,1 ΔE76 (O(n)), метки уточняются на полной копии; прогресс уходит на страницу |
| Posterize | там же | полосы L* (2…8 по Details) и грубые шаги a*, b* вместо уровней по каналам sRGB: тёмно-серый фон остаётся серым, а не фиолетовым; мелкие области поглощаются |
| Лимит цветов | там же | k-means по цветам пятен с весом √площади, чтобы тонкий чёрный контур получил свой кластер; тёмные элементы входят в тот же лимит |
| Тонкие тёмные элементы | там же | пиксель несглаженной копии темнее своего пятна на ΔL* ≥ 18 (настраивается) остаётся тёмным, пятно усредняется без него. Возвращает дотворк и штриховку флэша |
| Sketch | `core/drawing.ts` | XDoG: разность двух гауссов (три box-прохода, O(n)) с мягким порогом, плюс «локальная темнота» (L* минус широкий blur), чтобы толстый чёрный контур оставался сплошным, а не превращался в две линии. Stroke меняет sigma, Line — порог |
| Contours | там же | Canny: blur, Собель, подавление немаксимумов, гистерезис, обрывки короче 12 px выкидываются; Stroke штампует диск по линии |
| SVG | `core/vector.ts` | маска линий обводится по краям пикселей (на седловых точках поворот к краске, так что пиксели, касающиеся углом, не склеиваются), лесенки выпрямляются RDP с допуском 0,7 px. Один `<path>` с even-odd, прозрачный фон |
| PNG без фона | `Engine.exportInkPng()` | линии с альфой = покрытие. Для Procreate: SVG он не импортирует ([справка Procreate](https://help.procreate.com/articles/zyjjpk-importing-images)) |

Решения по умолчанию: Clustering, Details 5 из 9, без лимита цветов, тёмные элементы выключены (ΔL* 18); Drawing Sketch, Line 50, Stroke 2. Смена Line в Drawing пересчитывает только порог, размытие и градиенты кэшируются.

## Проверки

```bash
npm ci
npm test            # Vitest: цвет, ΔE2000 (пары Sharma), палитра и маркеры, Highlight, Simplify, Drawing, SVG, пороги, совместимость, прототип, заголовки
npm run check       # svelte-check + TypeScript
npm run build
CHROMIUM_PATH=... npm run test:gpu   # headless Chromium: сверка GPU и CPU, открытие 12 и 48 МП, палитра, маркеры, Highlight, Simplify, Drawing, SVG
```

- Паритет с прототипом (`test/prototype/csalgo.mjs`): L*, Notan (медиана и Otsu), нейтраль Temperature, вывод Values при одинаковых порогах (MSE L* ≤ 1). k-means у нас подгоняет гистограмму не хуже прототипа.
- Сверка GPU и CPU (кнопка на странице и `test:gpu`): 20 режимов на 4 фото (4 Highlight, 5 Simplify/Drawing: результат CPU против показа на GPU, заодно время расчёта на 1024×768), условие MSE L* ≤ 1 и не больше 0,5 % пикселей с разницей больше 2. Её можно запустить и на iPhone.
- SVG проверяется обратной растеризацией: обводка без упрощения даёт ровно исходную маску (дырки и касания углом тоже), с упрощением IoU > 0,9.
- Цифры Chromium (SwiftShader) не переносятся на Safari. Цели этапов (превью 12 МП ≤ 1,5 с, слайдер ≤ 50 мс, пауза главного потока ≤ 100 мс; палитра ≤ 500 мс, Highlight ≤ 50 мс, маркер = цвет образца; Clustering ≤ 1 с, Graph ≤ 3 с с индикатором) проверяются на устройстве.

Тестовые фото не дублируются: 1K-эталоны лежат в `test/fixtures/` (их генерирует `experiments/src/gen.py`), синтетика 12/48 МП берётся из `../stage0-bench/public/samples/` при сборке.
